# lcc 1.3.0

Draft notes for the GitHub Release. Full detail: [CHANGELOG.md](../../CHANGELOG.md#130---2026-10-31).

```sh
pip install -U "local-context-compiler[tiktoken]"
lcc fetch-tokenizer        # once: exact token counts
```

If you use the Claude Code plugin, update it from `/plugin` as well, so the hook and the `lcc`
it calls are both 1.3.0.

## First run is fast and exact

- **`lcc measure-session` runs the two rules modes by default; `auto` needs `--auto`.** On 1.2.0
  the `auto` arm took 247 s of a 4 min 15 s run on a 10,559-message session, so the README's
  first command looked hung. On a ~520k-token session the default now returns in about 2 s
  (one machine, 2026-10-28). The JSON report's `modes` list has two rows unless `--auto` is passed.
- **`lcc fetch-tokenizer`** downloads tiktoken's `cl100k_base` and `o200k_base` once into
  `~/.cache/lcc/tiktoken`, and lcc uses that directory when `TIKTOKEN_CACHE_DIR` is unset.
  Before, a fresh `pip install "...[tiktoken]"` still counted approximately, because lcc blocks
  the download to stay offline. Normal operation is still offline; this command is the explicit
  exception.

## Added

- **Stash lifecycle:** `lcc stash ls`, `lcc stash verify <session.jsonl>`, `lcc stash gc`.
- **Lean stash pointer, opt-in** (`--stash-pointer lean`).
- **Receipt after every tool-call compaction pass**, and an opt-in local ledger with a Claude
  Code statusline (counts only, never sent anywhere). Recall records in the ledger with `LCC_LEDGER=1`.
- **`lcc measure-session --input-map`**: where a session's billed input tokens go, with the cache
  read/write split. `measure-session` also reads Codex CLI rollouts (#67, thanks @dailyun) and
  says why a count is approximate.
- **Aider chat history reader** (#63).
- **Intake:** dictation detection with reported filler removal, named readiness reasons, an
  advisory request category from a local classifier, and terminal listings of every speech edit.
- **`lcc share-stats`** and a `results` issue form for anonymous counts.
- **Continuous invariant harness** with a nightly fuzz job, and a cache contract checked in CI.

## Fixed

- `rules_mode: stashed` no longer re-stashes its own placeholders; lossless no longer re-dedupes
  a pointer (both found by the invariant harness).
- The stash placeholder no longer depends on `tiktoken`.
- Speech cleaning no longer drops content, turns questions into statements or re-cases text.
- `lcc explain` shows `replace` and `dedupe` decisions.
- Linear-time reference regexes and relationship graph on long sessions.

## Security

- HTTP server: tool errors no longer echo exception text (#73), and `lcc mcp --http` refuses
  host-disk access.
- Regex/quadratic denial-of-service fixes in speech cleaning and request-log redaction (#88).
- `LCC_DISABLE_NETWORK=1` is honored everywhere; `lcc explain` escapes terminal control characters.
- Stash gc hardening; GitHub Actions pinned to commit SHAs.

## Changed

- Every prompt template puts per-request content last (prompt-cache friendly).
- Intake no longer blocks on security words, and its brief carries only what the input states.
- `auto` stays local for plain text.
